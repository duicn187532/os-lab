問題：找得到 ≠ 用對版本

Figure 1 的兩個對照例子原文 Figure 1

B. 狀態追蹤能力：先說「我們有 1600 筆標註資料要分析，5 位標註員，總預算 $600」。後來使用者說「其實改成 1200 筆」。再問「目前預算多少？」系統取回 {budget = $600} 並當成現況回答：狀態漂移（state drift）。

你跟朋友說「我要買 3 顆蘋果，每顆 10 元，總共 30 元」。後來你改口「買 2 顆就好」。朋友記得你說過的每一句話，結帳時卻還是說「30 元」。

狀態漂移的定義（§3）：先前對話建立或更新過的事實、限制或依賴關係確實在組好的 context 裡，但 agent 依據的是過期或不完整的版本，而不是決策當下有效的那一版。

漂移與檢索失敗正交：在 oracle 檢索（正確新值確定在 context 中）的設定下仍會發生，錯誤來自版本選擇，而非召回。
把整段對話直接塞進 context，在這個評測上會是最強的嗎？（答案在 08）
打開模型的推理，能不能修好「用到舊值」的錯？（答案在 03）

為什麼更好的檢索修不好狀態漂移？

定義上，漂移發生時正確的新值已經在 context 裡了。錯的是 agent 選了舊版本來用，問題出在「哪一版有效」的判斷，不在「找不找得到」。
